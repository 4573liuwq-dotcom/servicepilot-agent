# ServicePilot 简历与面试指南

## 简历项目描述

> **ServicePilot 电商售后智能客服 Agent**：基于 LangGraph 构建意图识别、订单查询、政策 RAG、售后决策、风控审核和动作执行工作流；使用 LangChain 结构化输出约束意图与退款决策，通过 `interrupt/resume` 实现高金额退款人工审批；设计 SQLite 订单工具、七天退货规则、幂等执行和审计日志，支持物流查询、退款与工单闭环，并通过 FastAPI 和 Web 工作台提供服务。

可以拆成简历要点：

- 将售后流程建模为 LangGraph 状态机，按意图、订单状态、风险等级动态路由。
- 基于 RAG 检索退换货与物流政策，要求模型输出政策证据 ID，降低无依据承诺。
- 对超过 200 元退款使用 HITL 中断恢复；拒绝审批时保证不执行数据库写操作。
- 使用幂等键防止接口重试造成重复退款，并记录可追溯业务流水与审计日志。
- 编写覆盖订单查询、高风险审批、超期退货、拒绝不执行和 API 的自动化测试。

## 一分钟面试介绍

“我做的不是通用聊天机器人，而是一个电商售后 Agent。用户提出问题后，系统先识别意图和订单号，再查询真实订单状态，并从售后政策库检索规则。决策 Agent 只能输出 answer、create_ticket 或 refund 三种结构化动作，代码层还会校验退款金额和七天退货期。超过 200 元的退款会通过 LangGraph interrupt 暂停，主管批准后使用同一个 thread_id 恢复并执行。执行层使用幂等键防止重复退款，同时记录业务流水和审计日志。”

## 高频追问

### 为什么要用 LangGraph，不用 if/else？

小流程用 if/else 当然可以。这里使用 LangGraph 的价值在于持久状态、中断恢复、节点级观测和后续多轮扩展。特别是人工审批可能等待数小时，普通函数调用无法自然保存和恢复上下文。

### 模型判断错了会不会乱退款？

不会让模型直接写数据库。模型输出结构化建议，确定性代码校验金额、时间和风险规则，高金额必须人工批准，执行工具还有幂等保护。生产环境还需订单归属鉴权和支付沙箱。

### 如何评测这个 Agent？

构造带订单、政策和预期动作的测试集，分别衡量意图准确率、订单号提取率、政策召回率、政策引用正确率、违规退款率和人工转接率。业务安全指标应优先于回答“看起来是否流畅”。

### RAG 的政策更新怎么办？

文档应携带版本、生效日期和部门元数据。检索时只选择当前生效版本；新政策发布后重建索引，并用历史问题做回归测试，避免新旧政策同时命中。
