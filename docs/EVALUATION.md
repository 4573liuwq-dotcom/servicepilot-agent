# 售后智办实验与消融说明

## 当前验证结果

| 方案 | 自动化用例 | 通过 | 外部LLM | 说明 |
|---|---:|---:|---|---|
| 规则/模板基线 | 17 | 17 | 否 | 可重复CI与现场演示 |
| 去掉人工审批 | 1个高额退款场景 | 不允许执行 | 否 | 299元退款必须暂停 |
| 去掉幂等保护 | 重复退款场景 | 风险项 | 否 | 当前实现复用原流水且只写1条动作 |
| 真实LLM结构化理解 | 待建立固定评测集 | 待测 | 是 | 不在README中虚构指标 |

`scripts/demo_support.py`会真实调用FastAPI应用完成物流查询、高金额退款暂停、管理员批准、恢复执行和重复退款验证。重复请求返回第一次的`reference_id`，且`action_count`仍为1。

## 为什么这里不用“准确率91%”

当前17项是功能回归测试，不是独立测试集上的模型准确率。仓库只报告可复现的“17/17通过”；后续建立包含口语表达、缺失订单号、越权请求和边界金额的人工标注集后，再统计意图准确率、违规执行率、审批召回率和端到端耗时。

## 后续实验

1. 固定100条脱敏售后问句，比较规则基线与真实LLM的意图准确率。
2. 按退款金额和收货天数分桶，统计违规自动退款率（目标为0）。
3. 注入重复、并发和审批恢复请求，验证幂等与状态恢复。
4. 对政策检索分别使用关键词、Dense和Reranker，统计Hit@3和平均延迟。
